# Lab 4 - 实现 sys_linkat、sys_unlinkat、sys_fstat syscall

## sys_linkat、sys_unlinkat 实现思路
sys_linkat 首先查询原文件对应的 inode 编号，再创建包含新文件名和原 inode 编号的目录项，使两个文件名指向同一个 inode，共享文件内容

sys_unlinkat 查找并移除指定文件名对应的目录项，将剩余目录项重新写回根目录。随后统计指向该 inode 的目录项数量：存在其他硬链接时保留文件；硬链接数量为零时，根据文件的打开情况决定回收时机。仍被打开的文件延迟至最后一次关闭后回收，无打开引用的文件则直接释放 inode 编号及其占用的数据块

本地跑 ci 测试时跑超时了，故设计 FileWriterBuffer 避免 call 太多 sync 方法，转为积累到一定程度再写回，故 OSInode 的 Drop 逻辑也修改为先 call `fn flush_write_buffer` 以同步块 cache 状态再完成其原来职责。

## ch6 简答问题

- 在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？
root inode 是 easy-fs 根目录的索引节点，编号固定为 0，是文件查找的起点。它记录根目录的大小、类型和数据块索引。系统通过这些索引读取根目录中的目录项，再根据文件名找到目标文件的 inode 编号，完成文件定位。

如果 root inode 中的目录大小、类型或数据块索引损坏，文件系统可能无法正确读取、遍历根目录，导致文件查找、打开和应用程序加载失败。文件自身的 inode 和数据块仍可能保持完整，需要恢复根目录元数据才能重新通过文件名访问。对于已经打开的文件，只要其自身的 inode 和数据块完好，仍可能继续读写。

## ch7 简答问题

- 举出使用 pipe 的一个实际应用的例子
用 cat file.txt | wc -l 统计文件行数。Shell 将 cat 的标准输出连接到管道写端，将 wc 的标准输入连接到管道读端。cat 读取文件并输出内容，wc -l 从管道读取数据并统计换行符数量。所有写端关闭且剩余数据读完后，wc 收到 EOF，结束统计。

- 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。
可以设计基于信箱的消息传递机制，为每个进程维护一个由内核管理的消息队列。发送方通过目标 PID 指定接收进程，内核将包含发送方标识和消息内容的数据加入目标信箱；接收方通过统一接口取出消息。内核负责队列的互斥访问、容量限制、等待处理和退出时的资源回收。这样，每个进程只需维护自己的接收队列，通信双方无需预先建立专用管道。
类似 Windows 原生 GUI 程序那样子的 Event 队列和 event loop 监听风格
